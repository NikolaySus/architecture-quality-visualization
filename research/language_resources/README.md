# Локальные языковые ресурсы

Пять локальных источников питают общее исследовательское представление русского
языка. Первая версия предоставляет типизированный граф в SQLite, происхождение
объектов и связей, поиск и отдельный GUI на Streamlit.

## Быстрый запуск

Выполняйте команды из корня репозитория. Требуется Python 3.12 и uv.

```powershell
uv sync --locked --group language-resources
uv run --group language-resources python -m streamlit run research/language_resources/app.py --server.address 127.0.0.1 --server.port 8502
```

GUI доступен по адресу http://localhost:8502. Для первой подготовки данных выполните
`uv run --group language-resources python -m research.language_resources sync`.
Команда `sync` возвращает код 2, если хотя бы один источник
частичен или недоступен. Подробности сохраняются в статусе, а сборка использует
доступные активные снимки. Код 1 означает ошибку выполнения или занятую блокировку.

Исходные данные, архивы, HTTP-кеш, базы, журналы и временные файлы находятся в
`work/`, который полностью исключён из Git локальным `.gitignore`. Первая загрузка
обращается к сети. GUI и `rebuild` работают с локальными данными офлайн.

## Загрузка и обновления

```powershell
# Только загрузить выбранные источники
uv run --group language-resources python -m research.language_resources download --source ud ruwordnet

# Проверить обновления выбранного источника и обновить зависимое представление
uv run --group language-resources python -m research.language_resources sync --source framebank

# Пересобрать локальные снимки и посмотреть состояние
uv run --group language-resources python -m research.language_resources rebuild
uv run --group language-resources python -m research.language_resources status

# Посчитать компоненты связности текущей сборки
uv run --group language-resources python -m research.language_resources components

# Принудительно собрать новое поколение
uv run --group language-resources python -m research.language_resources rebuild --force
```

Каталог `sources.json` содержит URL, состав ресурсов и сведения об условиях
использования. Для GitHub загрузчик разрешает HEAD в Git SHA и получает архив
конкретного коммита. Манифест снимка сохраняет версии, URL, время, компоненты,
размеры и SHA-256 каждого файла. HTTP-проверки обновлений используют ETag или
Last-Modified, когда сервер предоставляет эти заголовки.

Загрузчик пишет в новый staging-каталог. Проверенный снимок получает идентификатор
по содержимому и становится активным. При ошибке предыдущий активный снимок
остаётся доступен. Каталоги неудачных попыток сохраняются для диагностики, их пути
указаны в `status`.

Обновление центральной базы запускается командой `sync` после загрузки. Для данных,
принятых командой `import`, выполните `rebuild`. Отпечаток сборки включает снимки,
версию схемы, правила и код ETL. При совпадении входов повторная сборка пропускается.
Каждая сборка проходит проверку файлов источников, всех внешних ключей и структуры
SQLite через `quick_check`. Для завершающих проверок установлен лимит кеша SQLite
в 1 ГБ, чтобы удерживать ключи родительских объектов в памяти.
Готовое поколение публикуется через атомарное переключение указателя. GUI открывает
поколения для чтения и показывает расхождение с актуальными снимками источников.

Полная сборка сначала записывает утверждения в промежуточную SQLite-базу,
затем объединяет их по ключам и строит индексы. Промежуточная база удаляется после
объединения. Во время пересборки место занимают исходные снимки, предыдущее
поколение, промежуточные записи, новое поколение и файлы сортировки SQLite.
Производное представление может существенно превосходить исходные выгрузки по
объёму из-за объектов, связей, происхождения и индексов.

Старые снимки, поколения баз и неудачные загрузки сохраняются локально. Поэтому
потребление диска растёт с числом обновлений. Их можно удалять после проверки,
что они не указаны в `work/sources.json` и `work/current.json` и не используются
открытым GUI. Остановите загрузку и GUI перед ручной очисткой.

## Ручной импорт

```powershell
uv run --group language-resources python -m research.language_resources import semontocor 'C:/datasets/SemOntoCor.zip' --complete
uv run --group language-resources python -m research.language_resources import ruwordnet 'C:/datasets/ruwordnet-2021.db' --complete
uv run --group language-resources python -m research.language_resources import framebank 'C:/datasets/exampleindex.csv' --complete
uv run --group language-resources python -m research.language_resources rebuild
```

Можно передать каталог, ZIP/TAR-архив или отдельный исходный файл. Импорт копирует
выгрузку в новый снимок. Для FrameBank отдельный `exampleindex.csv` дополняет копию
текущих таблиц. Каталоги и архивы заменяют состав источника целиком, поэтому они
также позволяют убрать записи при очередной загрузке.

Флаг `--complete` фиксирует, что пользователь проверил полноту ручной выгрузки.
Дополнительно проверяется наличие обязательных компонентов. Без флага статус
полноты ручного импорта остаётся неподтверждённым. Неполнота отображается в GUI.

Для отдельного рабочего каталога задайте переменную `LANGUAGE_RESOURCES_HOME`
или глобальный аргумент CLI `--home PATH` перед названием команды. GUI использует
ту же переменную окружения. Правило Git-ignore в этом модуле относится к
стандартному `work/`.

## Состав и особенности источников

| Источник | Извлекаемые данные и доступность |
|---|---|
| UD | SynTagRus, Taiga, GSD, PUD, Poetry. Предложения, документы, токены, многословные токены, пустые узлы, леммы, морфология, основные и расширенные зависимости. Вспомогательная папка `not-to-release` исключена из ETL. |
| RuWordNet | База 2.0, синсеты, значения, леммы, внутренние отношения и присутствующие межъязыковые соответствия. SQLite источника открывается через `mode=ro`. |
| FrameBank | Четыре основные TSV-таблицы и отдельный `exampleindex.csv`. Облачный файл примеров может возвращать HTTP 403. Основные таблицы доступны независимо, отдельный импорт файла примеров дополняет их. |
| SemOntoCor | Рекурсивная выгрузка публичной папки Drive. Текущий адаптер читает Graphviz SVG с текстовыми заголовками узлов, рёбер и кластеров. Полнота означает покрытие опубликованной папки, размер которой может отличаться от полного корпуса, описанного в статьях. Если каталог возвращает ровно 50 файлов, требуется дополнительная проверка полноты. |
| AMR | Исходные английские графы MASSIVE-AMR и оригинальные русские и английские записи MASSIVE 1.1. Русские предложения связаны с английскими по исходным ID. Локализованные графы получают правило `massive-authors-localization-v1`. |

Для AMR применяется замена именованных сущностей по типизированным слотам,
воспроизводящая процедуру авторского notebook. `definition_word` исключается из
локализации, как в авторском коде. Несогласованные слоты сохраняются как причины
отсутствия локализованного графа в карточке русского предложения. Исходный
английский граф и связь параллельных предложений остаются доступны.

В SemOntoCor подписи кластеров представлены отдельными объектами
`surface_fragment`. Геометрическое расположение элементов SVG сохраняет
визуальный контекст исходной выгрузки. Первоначальный адаптер извлекает явные
узлы и рёбра, а соответствия кластеров семантическим узлам можно добавить
следующей версией правил.

## Центральная схема и правила

`source_snapshot` хранит измерение версий источников. `entity` содержит типизированные
объекты. `relation_type` задаёт измерение типов отношений. Центральная таблица
`fact_relation` связывает субъект, тип отношения, объект и происхождение факта.
`entity_evidence` связывает объект с исходными файлами и записями. В `metadata`
сохранены входы и результаты сборки.

Идентификаторы объектов вычисляются из источника, пространства имён, типа и
исходного идентификатора. Версия снимка учитывается отдельно. Нативные атрибуты
доступны в поле `raw` карточки объекта. Отношения сохраняют свои пространства
имён, например `ud:obj`, `ruwordnet:hypernym` и `semontocor:hasAgent`.

Явные русские леммы связываются с общими узлами `lexicon:ru` отношением
`lexical:lemma_match`. Нормализация использует NFC, casefold и свёртку пробелов,
сохраняя различие `е` и `ё`. Части речи сохраняются в атрибутах соответствия.
Узлы значений и концептов сохраняют исходные идентификаторы. Вхождения слов и
лексемы различаются типами. Для FrameBank используются русские лексемы из
`KeyLexemes`, включая конечные цифровые индексы омонимов. Например, `хватать2`
связывает самостоятельную конструкцию с лексемой `хватать`. В атрибутах связи
сохраняются `raw_key` и `homonym_index`, правило — `framebank-key-lexeme-v2`.
Неподдерживаемые непустые ключи попадают в диагностику с файлом, записью и причиной.

Многословные опубликованные леммы получают отношения `lexical:has_component`
к лексемам составляющих слов с правилом `published-lemma-components-v1`.
Токенизатор сохраняет дефисные слова целиком. Каждая связь содержит исходную
лемму, компонент, позицию и символьные границы в исходной лемме, а также файл
и запись источника. Повторные слова имеют отдельные позиционные связи.
Отношение описывает состав опубликованной леммы. Морфологическая корректность
компонентов наследуется от источника. Значения сохраняют собственные узлы.

SemOntoCor и русские предложения MASSIVE-AMR дополнены слоем `word_occurrence`.
Каждое вхождение имеет стабильный ID по предложению и символьным границам,
позицию и связь `text:contains_word` с минимальным однозначно сопоставленным
текстовым фрагментом. Для SemOntoCor используются кластеры SVG, для AMR создаются
`surface_fragment` из размеченных слотов MASSIVE. Вложенные и пересекающиеся
фрагменты используют общие вхождения. При одинаковых минимальных границах
сохраняются связи со всеми соответствующими фрагментами. Для слов за пределами
сопоставленных фрагментов контейнером служит предложение.

Русские синсеты RuWordNet получают отдельные `surface_fragment` для непустых полей
`title` и `definition`. Отношения `ruwordnet:title_text` и `ruwordnet:definition_text`
соединяют синсет с текстом поля. Правило извлечения — `ruwordnet-text-fields-v1`.
Внутри поля выделяются сбалансированные круглые скобки, включая вложенные
и повторные уточнения. Их фрагменты соединяются через `text:contains_fragment`
и сохраняют исходный текст, поле, владельца и символьные границы.
Несбалансированные скобки учитываются в диагностике, полный текст поля доступен
для исследования и токенизации.

Словоупотребления создаются один раз на поле и соединяются через
`text:contains_word` с наименьшим однозначно сопоставленным фрагментом.
В атрибутах указаны `text_container_id`, `source_field`, `source_record`
и `source_entity_id`. Позиции и границы отсчитываются от начала исходного поля.
Идентификаторы включают синсет, поле и границы. Разрешённые леммы получают обычные
лексические связи с происхождением UD. Эта цепочка описывает упоминание слова
в тексте синсета. Исходные значения и смысловые отношения имеют собственные узлы
и типы связей. Например, уточнение «сплав ртути» сохраняет контекст химического
употребления «амальгамы». Поля английских синсетов импортируются в исходном виде.

Токенизация выполняется один раз на предложение, пунктуация и служебные скобки
разметки исключаются. Повторяющиеся фразы требуют однозначного положения в тексте.
Для слотов MASSIVE позиции восстанавливаются из `annot_utt`, включая одинаковые
повторные значения. У вхождений сохраняются границы в исходной строке предложения.
Позиции отсчитываются от нуля, правая граница интервала исключается.

UD обрабатывается первым, словарь словоформ строится за тот же проход по токенам.
Наблюдения с `Typo=Yes` в поле `FEATS` исключаются из словаря соответствий.
Исходные токены и их опубликованная разметка полностью импортируются.
Если оставшиеся наблюдения дают единственную лемму, вхождение получает связь с
общей лексемой с правилом `unambiguous-clean-ud-form-v2` и ссылкой на запись UD
без этого признака. Результат разрешения одинаков при любом порядке наблюдений.
Поле `lemma_status` сохраняет значения `ud_form` и `unresolved`. Дополнительное
поле `lemma_reason` принимает `unique_lemma`, `ambiguous_form`, `absent_form`,
`typo_only` или `ud_unavailable`. Связывание требует единственной допустимой леммы.
Версии обоих источников учитываются в отпечатке сборки и происхождении данных.

Сводка обработки сохраняется в `generation.diagnostics` и доступна через `status`
и раздел GUI «Источники» → «Диагностика обработки». Она содержит числа наблюдений
UD с опечатками и без них, однозначных и неоднозначных форм, причины разрешения
словоупотреблений, обработанные индексированные ключи FrameBank, пропуски и числа
утверждений о компонентах. Счётчики утверждений относятся к записям до объединения
дубликатов при сборке. Для RuWordNet дополнительно доступны числа полей,
словоупотреблений, скобочных фрагментов и несбалансированных скобок.
Версия правил — `explicit-lexical-and-words-v4`.

Этот формат допускает последующее добавление соответствий, уточнение типов и
экспорт разреженных координат с отдельными словарями осей для будущего тензорного
представления. Текущая версия предназначена для исследования объединённых данных.

## GUI и проверки

GUI содержит статус пяти источников, FTS5-поиск с фильтрами и пагинацией,
карточки происхождения и интерактивную окрестность объекта. В графе доступны
масштабирование, перемещение, подсказки и переход к новому корню. Глубина
составляет 1–3 перехода. Пределы узлов и связей настраиваются в GUI любыми
положительными целыми числами, по умолчанию 200 и 5 000. Усечение явно
отображается. JavaScript графа включён в HTML для работы офлайн.

```powershell
uv run --group language-resources python -m pytest tests/test_language_resources.py tests/test_language_connectivity.py -q
```

Тесты создают небольшие искусственные источники. Они проверяют пять адаптеров,
неизменность исходных файлов, повторную сборку, изменение и удаление записей,
аварийное завершение, безопасную распаковку, сохранение разных значений общей
леммы, происхождение, границы графа и пустой/частичный GUI. GUI-тестам Streamlit
нужны локальные сокеты.

Команда `components` учитывает все типы связей, включая производные, и игнорирует
направление рёбер. Она читает одно зафиксированное поколение базы и сохраняет
число компонент, размеры крупнейших и доли объектов каждого источника в
`work/analysis/connectivity-<generation>.json`. Общие лексемы учитываются в
отдельной группе `shared`. Подсчёт включает изолированные объекты и выполняется
потоковым алгоритмом объединения компонент.
Флаг `components --details` сохраняет в `work/analysis/connectivity-details-<generation>.json`
все объекты остальных компонент, их связи и происхождение для исследования причин изоляции.
