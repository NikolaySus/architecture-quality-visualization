# Предсказание качества архитектуры

Локальный исследовательский каталог по `architecture_quality_visualization_handoff.md` v0.2. Русскоязычное приложение, воспроизводимый импорт, PDF-отчёт и экспорт графиков. GPU, LLM API и обучение кандидатов не нужны.

## Запуск через uv

```bash
uv sync --locked
uv run streamlit run app.py --server.address 127.0.0.1
```

Проект закрепляет Python 3.12 в `.python-version`, зависимости - в `uv.lock`. Откройте http://localhost:8501. После установки зависимостей приложение работает без обращения к внешним сервисам; ссылки на статьи открываются по запросу пользователя.

Готовый отчёт: [output/pdf/architecture_quality_report.pdf](output/pdf/architecture_quality_report.pdf).

```bash
uv run python scripts/build_report.py
uv run python scripts/validate.py
uv run pytest -q
```

Для сборки PDF используется установленный в Linux шрифт DejaVu Sans (`/usr/share/fonts/truetype/dejavu`). Для проверки растрового представления PDF нужен `pdftoppm` (Poppler). Экспортированные SVG/PNG/PDF и CSV находятся в `exports/`; параметры каждого графика включают метрику, группу, шкалу и версию корпуса.

## Что импортировано

- 50 источников P01-P50, с исходными уровнями F/A/M. Полные авторские списки пока не извлечены; исходная библиографическая строка сохранена.
- 72 метода M01-M72. M35 проверен по полному тексту (CV, синтетические входы/targets); M72 исключён до проверки реализации. Evaluation paper хранится отдельно.
- 68 наблюдений: G1=15, G2=8, G3=5, G4=11, G5=12, G6=6, G7=5, G8=6. Отдельно 5 записей контекстных затрат, включая discovery и амортизированные признаки.
- Временная запись ZeroLM связана с кандидатами M26/M27 и не дублируется. Варианты M46 разделены; каждый бюджет G5/G7 - отдельное наблюдение.

Корпус - это отобранный обзор, а не исчерпывающий систематический поиск. Исходные уровни проверки из handoff не означают независимого воспроизведения. Адресная дополнительная проверка трёх первоисточников зафиксирована в `data/research_checks.json`; unresolved поля не переименованы в `not_reported`.

## Визуализации и ограничения

D в PDF: категориальный 2D-график с пятью точками и пять таблиц для 69 допущенных методов. Аудит `data/access_audit.json` закрывает 32 из 35 пробелов; M28, M40, M72 исключены и перечислены в конце PDF. Требования относятся к конкретному варианту и включают получение признаков нового кандидата; setup описан отдельно. Исходные 72 записи сохранены без изменения, `corpus.load()` применяет проверенный overlay. G3/G7/G8, неоднозначный ZeroLM и непроверенные NLP-адаптации не попадают в основное сравнение; исходные числа сохранены в конце. В PDF A/C не строятся без проверенных затрат; в приложении предварительные времена доступны только для допущенных наблюдений.

B показывает требования при применении внутри одной группы. Вариант SynFlow для NLP не наследует автоматически data-free характеристику origin paper. Требования setup, historical labels и синтетические входы сохраняются отдельно. C содержит пустое состояние и контекстные затраты: совместимых полных setup/query пар нет, поэтому калькулятор суммарной стоимости не включён. F показывает независимые панели G1/G2/G4; их различия нельзя приписать только смене входов. Численные результаты G8 доступны по отдельным группам и метрикам.

На графике цвет/контур относится к архитектурам **наблюдения**, в каталоге - к максимально подтверждённому применению **метода**. Серый полупрозрачный круг имеет настоящий пунктир; синий означает NLP Transformer. Третий класс text embedding остаётся в легенде с нулём работ. LM внутри CV-предиктора не меняет домен кандидатов.

Неизвестные затраты - `null` или пустой массив, никогда 0. `candidate_query_cost` не заполняется предварительным `reported_average_time`. Исходные отрицательные корреляции сохранены; G3 не подвергается sign normalization. Полное обучение служит текстовым ориентиром: численной сопоставимой baseline стоимости нет. Исторические labels не считаются бесплатными только потому, что уже доступны в benchmark.

Точка SVG содержит hover с полной записью и ссылку на карточку в новой вкладке. Карточку также можно выбрать в списке. Фильтры охватывают класс/домен, семейство, требования применения и группу. Пакет экспорта содержит график, исходные данные и параметры отбора. Каждое исключённое наблюдение имеет причину.

## Данные и добавление записей

`data/papers.json`, `methods.json`, `observations.json` редактируются независимо от кода визуализаций. `groups.json` содержит описание протоколов; `context.json` - затраты, которые нельзя соединить с корреляцией. `manifest.json` закрепляет источник и SHA-256. Полные формулировки handoff сохранены в raw-полях.

1. Добавьте paper с уникальным P-ID, первичной ссылкой, уровнем проверки и библиографией. Не угадывайте authors, версии и даты.
2. Добавьте method с origin/evaluation ссылками, классом или `null`, семейством, требованиями входов и setup. Новый evaluation не создаёт новый метод.
3. Добавьте observation с уникальным ID, точным `method_variant_id`, evaluation paper, метриками, evidence URL/version/locator и явной comparison group. Для неопределённого варианта используйте `method_id: null` и `method_candidates`.
4. Не объединяйте разные scopes времени. Для полного query-time нужны `scope: candidate_query`, `hardware`, `accounting_completeness: verified`; отдельная `comparison_group_id` должна подтверждать сопоставимость аппаратуры и протокола. Производные числа требуют формулы.
5. Запустите валидацию и сборку отчёта. Новые группы и варианты появляются в приложении без правки графического кода. PDF v0.2 содержит явно выбранные панели G1-G7, а полный табличный реестр строится из данных.

Повторный импорт исходного handoff:

```bash
uv run python scripts/import_handoff.py
```

Эта команда **перезаписывает** импортированные JSON исходным срезом v0.2; не запускайте её после ручного расширения корпуса без сохранения изменений. `research_checks.json` она не перезаписывает.
